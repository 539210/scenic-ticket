# 业务规则

本文件记录已确认规则。除非课程要求发生直接冲突，不再就这些规则反复询问。

## 优先级

1. 数据正确。
2. 业务流程正确。
3. 权限安全。
4. 现场演示稳定。
5. 测试充分。
6. 界面易用。
7. 高级功能。

## 票种、日期和库存

- 一个景点可有多个票种，至少支持成人、儿童、学生，管理员可扩展。
- 票种有独立价格、优惠和上下架状态。
- 用户必须选择未来有效游玩日期；每票种每日期有独立库存。
- 景点或票种下架、日期过期或库存不足时禁止下单。
- 库存不可小于零；使用 MySQL 事务和行锁/等效原子条件更新防超卖。
- 退款恢复同一票种、同一游玩日期的库存。
- 票种和库存维护不接受 UI 计算的可售量；管理员只提交总库存，服务在锁定库存行后用 `总库存 - 已预留 - 已售` 重算可售量。
- 库存事务中的票种校验与库存 `FOR UPDATE` 必须复用同一 JDBC 连接，避免连接池耗尽，也保证校验与扣减处于同一事务视图。

## 订单与支付

- 服务层根据票种、优惠和数量重新计算金额，绝不信任 UI 金额。
- 创建订单状态为待支付；用户查看后主动确认模拟支付，成功后才变为已支付。
- 保存票种、原价、优惠、折后单价、数量、总额、日期、支付方式、创建/支付时间和状态快照。
- 合法转换：待支付→已支付；待支付→已取消；已支付→已取消并退款；已支付→已完成。
- 已取消不可恢复为已支付；已完成不可取消或退款；转换集中在服务层。
- 待支付订单默认保留库存 15 分钟；过期后取消并释放库存，不能再支付。
- 创建、支付、取消、过期和退款都先锁订单/库存并在单一 MySQL 事务内更新；MongoDB 行为审计只在提交后执行。
- 迁移前待支付订单若没有匹配的预留库存，过期扫描可以取消订单但不得增加可售库存；该兼容分支必须写警告，新创建订单不使用该宽松分支。

## 退款

- 仅当前日期早于游玩日期、未核销、未完成、未退款的已支付订单可退款。
- 退款、订单取消、退款记录和库存恢复在同一个 MySQL 事务完成。
- 成功后记录退款金额/时间并写审计；失败不得产生半完成状态。

## 核销

- 仅管理员可核销存在、已支付、未退款、未核销且日期有效的订单。
- 核销数量必须合法；全部数量核销后订单变为已完成。
- 已核销订单不可退款；核销写 `admissions` 和审计。
- 核销仅允许在订单 `visit_date` 当天执行；订单行锁串行化同一订单的并发核销，累计数量不得超过购票数量。
- 允许分批入园；仅当累计核销数量等于订单数量时，订单由已支付原子转为已完成。

## 评论

- 提交时必须存在该景点已支付且未退款订单；服务层必须再次校验。
- 每用户每景点一条评论；重复提交更新原评论。
- 评分 1..5，正文非空且限长，保存创建和更新时间。
- 标签最多 10 个，每个最多 30 字符；空白和重复标签在服务层清理。
- 后续退款可保留历史评论。
- 列表展示脱敏用户、评分、正文、标签和时间；简介、评论、行为日志、系统日志分区展示。
- 评论写入成功后行为日志失败不回滚评论；返回明确审计警告，避免用户误以为失败而重复提交。

## 管理员用户管理与授权

- 管理员可按用户名、邮箱、角色、状态查询，查看档案/订单/行为概况，启禁用户和调整普通用户角色。
- 管理员不能禁用自己，不能禁用/删除最后一个有效管理员。
- 普通用户不能调用管理员功能；服务层必须验证 actor，不以隐藏按钮替代授权。
- 管理变更写审计日志。
- 所有受保护服务必须接收当前 actor ID，并从 MySQL 回查账号仍为启用状态及当前角色；不得信任 Swing 中缓存的角色。
- 管理员状态和角色变更在同一 MySQL 事务内锁定 actor、目标用户和有效管理员集合，避免并发绕过最后管理员保护。
- MySQL 用户变更提交后才写 MongoDB 审计；审计失败不回滚已提交事务，返回“业务成功、审计失败”的明确警告并记录日志。
- 退出、返回登录页和新账号登录都会推进会话代次；旧异步任务可以完成后台读取，但其回调不得更新新会话界面。

## 跨数据库一致性

- MySQL 是订单、库存、支付、退款、核销的强一致事实源。
- MySQL 事务提交后 MongoDB 审计/行为日志失败，不回滚已提交 MySQL，也不能假装完全无异常。
- 应返回核心业务成功并明确记录告警，通过可重试 outbox/补偿记录完成日志补写；具体实现写入技术设计与迁移文档。
- 新增景点时 MySQL 基础记录先创建、MongoDB 详情随后写入；若详情写入失败，服务必须立即尝试将景点下架并返回明确告警，禁止无详情的新景点继续上架售卖。
- `item_details.item_id` 的规范类型为数值；读取兼容历史数字字符串，再次保存时使用原文档 `_id` 原位替换为数值 ID，避免复制出第二条详情。

## 数据库保护

- 真实集成测试仅用 `scenic_ticket_test`。
- 不清空或迁移本地 `scenic_ticket`，除非用户明确授权且有备份/回滚方案。
- 全新安装脚本与已有库升级脚本分开；升级脚本不得 drop 课程必需表/字段或指定 Mongo 集合。
