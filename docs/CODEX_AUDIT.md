## 架构观察（M0 快照与当前修复）

- `AppFrame.java` 已从页面巨石降至 885 行的窗口/权限/服务编排器；M9 已抽出完整后台、登录/注册、全部业务表单/查询弹窗及九个业务页面组件，以及任务/表格/策略/解析组件，最后收口景点与评论展示格式化边界。
- DAO 基本使用 PreparedStatement；动态 `IN` 仅动态生成占位符，不拼接用户值。
- M0 时订单只插入单表；M5 已改为订单与库存同事务的创建/支付/取消/过期/退款状态机，M6 已完成部分/全部核销、自动完成和退款排斥。
- M0 时 Mongo 日志失败会伪装 MySQL 失败；当前生命周期先提交 MySQL并返回明确审计警告。
- M0 时管理员检查仅存在于 Swing；M2 已统一服务层授权，M5 已停用任意订单状态接口。
- M0 时 MongoDB ID 只按 long；M3 已兼容字符串 ID 并在详情保存时原位规范化。

## M0 结论

M0–M8 的基线、授权、订单状态机、票种/日期库存、退款、核销、跨库 UTF-8、推荐和审计均已有自动与真实库证据；四个已知 UI 问题已验证。当前继续执行 M9 页面拆分与巡检，随后仍需完成 M10 真实桌面全流程和 M11 最终全量验收，不能提前宣称目标完成。

只读数据库复现进一步确认：当前 MongoDB 的简介和评论中文已实际损坏为问号，而不是本实例中的 ID 类型不匹配；推荐 Service 当前能产生非零分数；现有审计 user/type/level 组合可工作但完整目标条件缺失。详见 `docs/KNOWN_BUG_REPRODUCTION.md`。
