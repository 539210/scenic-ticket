# 五分钟答辩演示脚本

更新时间：2026-07-14

## 演示前准备

- MySQL、MongoDB 已启动，演示库已执行完整安装脚本。
- 准备管理员 `kongsc` 和一个普通用户；预先准备一个上架景点、今天/未来库存及一张可核销订单，避免现场等待。
- 窗口最大化，关闭无关通知；终端停在项目根目录。
- 先执行 `.\start-app.cmd --check`，再执行 `.\start-app.cmd`。

## 0:00–0:35 项目与架构

讲述：这是 Java 21 + Swing 桌面系统，MySQL 保存强一致的用户、票务、订单、退款和核销数据，MongoDB 保存景点详情、评论、行为和系统审计。DAO/Service/UI 分层，库存与订单生命周期使用 JDBC 显式事务和行锁。

展示：README 技术栈、应用登录页，不展开源码细节。

## 0:35–1:35 普通用户浏览与购票

1. 登录普通用户，展示只有五个用户侧页签。
2. 景点浏览查询，选中景点；依次点概览、简介、游客评论。
3. 展示推荐分/理由、UTF-8 简介、脱敏评论和评分。
4. 点击购买门票，选择票种、未来日期、数量；说明弹窗是下单前估算，成功页以服务端事务金额为准。

关键讲述：创建时是待支付并预留库存 15 分钟，不会直接变成已支付。

## 1:35–2:25 订单生命周期

1. 进入我的订单，展示票种、游玩日期、价格快照和待支付状态。
2. 点击确认支付，刷新后变为已支付。
3. 展示未来未核销订单可退款；说明退款记录、订单状态和库存恢复在同一事务。
4. 返回景点发表评论，再次提交会更新同一条评论。

关键讲述：按钮只显示合法动作，服务层仍会回查 actor、所有者和状态，不能靠隐藏按钮代替权限。

## 2:25–3:35 管理员后台

1. 退出并登录 `kongsc`，展示后台管理和系统审计页签。
2. 快速展示分类树、景点详情、票种与每日库存三段桶。
3. 用户管理按条件查刚才账号，展示档案/订单/行为概况和自身/最后管理员保护。
4. 门票核销对预备的当天订单先核销 1 张，再完成剩余数量，订单自动变为已完成。

关键讲述：库存 available/reserved/sold 全程在 MySQL 事务和行锁内变化，真实并发测试证明不超卖、不为负。

## 3:35–4:25 统计、审计与数据库高级对象

1. 统计报表展示月报、热门景点名称、用户报告和综合汇总。
2. 系统审计组合用户/类型/级别/日期/关键词查询，再展示汇总和趋势。
3. 口头说明两个视图、两个存储过程、两个触发器和至少三个 Mongo 聚合均有真实调用测试。

## 4:25–5:00 测试与结论

展示 `docs/M10_REAL_DATABASE_ACCEPTANCE.md`：

- 空库：10 表、12 外键、2 视图、2 过程、2 触发器。
- Day08 升级保留历史用户/档案/订单。
- M11 最终默认 158 项和真实数据库 172 项测试全部无失败/错误。
- 普通用户和管理员完整流程使用隔离 `scenic_ticket_test`，不会触碰本地业务库。

收尾：系统满足课程结构要求，同时补齐了权限、事务、迁移、并发、跨库降级和可答辩演示稳定性。

## 超时删减顺序

时间不足时依次删减：评论修改、用户管理详情、审计趋势。不得删减待支付→支付、库存事务、核销、真实测试结果四个核心证明点。
